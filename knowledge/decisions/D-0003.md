# D-0003 — The hand-built Blockbench project is the truck; `adopt.py` splits it and reads the profile off it

**Decision**: The truck's source is `devtools/art/preview/trailblazer.bbmodel`, built and
edited by hand in Blockbench (by Rusty's friend, then sized by Rusty). Nothing generates
it. `devtools/art/adopt.py` splits it into the shipped body and wheel projects and
writes the profile with every position and size read off the cubes -- the seats off the
cushions, the hit boxes off the fenders, the collision box off the hull (not the cage),
the chest's place and scale off the `chest_base` cube, the hitch off the ball, the radio
off the dash -- so the file may be rescaled or reshaped and the profile follows. The
gameplay numbers (engine, handling, climb, mass, fuel) stay in the script, for the
tuning session. A copy of the file as received is kept outside the repo.

**Why**: The friend's wheels and arches were plainly better than the generator's, and
the file is where a modeller works. A profile with hard-coded numbers from one size of
truck broke the day the file was scaled to fit the game (the seat put the driver's head
through the windshield's bar; the game's double chest swallowed a bed one block wide).
The collision box stops at the hull because a truck stopped by every low canopy is no
fun to drive, and a cage pushes through leaves.

**Alternatives rejected**: *Folding the friend's edits back into the generator* -- a
generator that must be taught every hand edit is worse than no generator. *A profile
edited by hand* -- it drifts from the file at the first rescale.
